JATAYU Console

Site Monitoring Console — UI/UX Design Showcase

Overview

JATAYU is an operator console for a prototype site-monitoring system featuring ESP32 CSI sensors and Arduino Mega gas sensors. The console provides auditable incident management for human review with a clean, modern interface inspired by HealthifyMe's design language.

Design Philosophy

  • Credible field-instrument aesthetic — Dense, information-rich layout without visual noise
  • Honest language — Clear, factual copy that doesn't overpromise
  • Accessibility-first — WCAG AA contrast, keyboard navigation, screen reader support
  • Mobile-responsive — Works on 390px screens with horizontal scroll for data tables
  • Offline-capable — No external fonts or CDNs, works without internet
  • Theme support — Daylight and Low light modes with system preference detection

Key Features

Next Action Guidance

Mint-tinted card that guides operators to the most important action, with clear priority ordering and contextual help.

Setup Checklist

Visual progress indicator showing system readiness across 6 checkpoints: backend connectivity, ESP32 streaming, signal quality, Arduino connection, gas sensor status, and monitoring state.

RF Observation Panel

Real-time periodicity score, pattern detection, confidence metrics, and live chart with periodicity history. Clear status indicators (Collecting, No clear pattern, Review, Pattern detected).

Environmental Sensor

Raw ADC readings, baseline tracking, elevated threshold monitoring, and warming-up state management. Chart shows readings over time with threshold visualization.

Incident Management

Two-column layout with incident ledger and detailed view. Evidence tracking, operator acknowledgements, note-taking, and audit trail. Status workflow: Open → Acknowledged → Closed.

Event Timeline

Complete audit trail of all system events: monitoring state changes, RF observations, command lifecycle, incident creation/acknowledgement/closure. Filterable by selected incident.

Device Commands

Command queue showing lifecycle: Created → Sent → Received → Executed → Acknowledged. Target device identification and failure tracking.

Sensor Nodes

Editable node registry with position (x, y, z), heading, antenna type, firmware version, and last-seen timestamp. Inline editing with validation.

Accessibility

  • WCAG AA contrast ratios (4.5:1 minimum)
  • Keyboard navigation with visible focus rings (2px mint outline)
  • ARIA labels on all interactive elements
  • Screen reader announcements for dynamic content
  • Reduced motion support via prefers-reduced-motion
  • Semantic HTML structure (header, main, section, nav)
  • Form labels and error messages
